# פריסה: שרת Linux יחיד

התבניות ב־`deploy/` מיועדות ל־NGINX ול־Node על אותה מכונה, עם MariaDB ברשת פרטית. הן אינן התקנה שבוצעה בשרת ציבורי. יש להחליף דומיין, נתיבי תעודות וסודות לפני שימוש.

## הכנה ופריסה

1. התקינו Node התואם ל־package.json, MariaDB ו־NGINX. הגדירו משתמש שירות `moneyjungle` ללא הרשאות מנהל. פתחו לציבור רק HTTPS ו־HTTP לצורך הפניה/חידוש תעודה; הגבילו SSH בנפרד. אין לחשוף 3000 או 3306.
2. העתיקו את הקוד ל־`/opt/moneyjungle`. הריצו `npm ci` בכל אחת מתיקיות backend ו־frontend ובנו עם `npm run build`. הבנייה דורשת גם devDependencies. אין להריץ שרת Vite לפיתוח בפרודקשן.
3. צרו `/etc/moneyjungle/backend.env` לפי `deploy/backend.env.example`, עם הרשאות 640 ובעלות root:moneyjungle. הגדירו משתמש DB ייעודי וסיסמה מקודדת ל־URL. הריצו מיגרציות באמצעות זהות פריסה בעלת הרשאות DDL; משתמש השירות השוטף צריך הרשאות נתונים בלבד.
4. צרו `/var/lib/moneyjungle/documents`, בבעלות משתמש השירות והרשאות 700. תיקייה זו חייבת להישמר בין גרסאות ולהיכלל בגיבוי. אין להציב מסמכים תחת root של NGINX.
5. גבו לפני מיגרציות. מתוך backend, עם DATABASE_URL מתאים, הריצו `npx prisma migrate deploy`. המיגרציה החדשה מוסיפה זמן פעילות לסשנים. אין להשתמש ב־`migrate dev` בפרודקשן.
6. התקינו את יחידת systemd, הריצו `systemctl daemon-reload` ו־`systemctl enable --now moneyjungle`. ודאו ש־`/api/health` עונה ישירות מהשרת; זו בדיקת חיות, לא בדיקת זמינות מסד הנתונים.
7. הנפיקו תעודת TLS לדומיין שבשליטתכם והתקינו את תבנית NGINX בהקשר http. הריצו `nginx -t` לפני טעינה מחדש. `PUBLIC_ORIGIN` חייב להיות בדיוק מקור ה־HTTPS, ללא לוכסן בסוף. `TRUST_PROXY=loopback` מתאים רק לפרוקסי המקומי הזה.
8. בדקו דרך HTTPS: כניסה, רענון בנתיב פנימי, טעינת מסמכים, ייבוא, יציאה וחסימת בקשות ממקור זר. ודאו ש־`__Host-mj_session` כולל Secure ו־HttpOnly ושה־API אינו נשמר במטמון. ודאו שפורטי האפליקציה וה־DB חסומים מבחוץ.

## אבטחה וגבולות המימוש

האימות משתמש בסשן אקראי שבשרת נשמר רק הגיבוב שלו. אין JWT או טוקן התחברות ב־localStorage. הדפדפן מחזיק Cookie מסוג HttpOnly; ה־Frontend מקבל הוכחת CSRF בזיכרון בלבד. כניסה קיימת נשמרת ברענון באמצעות `/api/gate/session`. סשנים ישנים מסוג Bearer מחייבים כניסה מחדש. ברירת המחדל: שבעה ימים לכל היותר ושעתיים ללא פעילות; זמן הפעילות מתעדכן לכל היותר פעם בדקה.

כל בקשה מאומתת, גם GET, דורשת X-CSRF-Token למעט bootstrap של הסשן. זו הגנה מכוונת משום שחלק ממסלולי הקריאה הקיימים מעדכנים רשומות נגזרות; הפיכתם לקריאה בלבד עדיין נדרשת. Origin נדרש לפעולות שינוי. משתמשים קיימים עם גיבוב סיסמה ישן משודרגים בכניסה מוצלחת.

מגבלת הכניסות נמצאת בזיכרון התהליך: פריסה למספר תהליכים מחייבת מאגר משותף. סיסמאות משתמשות ב־scrypt עם זיכרון משמעותי; יש למדוד את צריכת הזיכרון תחת עומס לפני קביעת מגבלות systemd. התבנית מתירה Google Fonts במפורש, ו־inline styles לצורך רכיבי התצוגה; scripts מוגבלים למקור האתר. אין לטעון HTML או scripts שהועלו בידי משתמשים מאותו מקור.

## גיבוי והתאוששות

גבו את MariaDB בכלי המתאים לגרסה, יחד עם תיקיית המסמכים ובאופן עקבי מבחינת זמן. שמרו גיבוי מוצפן מחוץ למכונה, הרשאות מוגבלות ומדיניות שימור. סודות ותעודות נשמרים בנפרד מהקוד. הגדירו יעד זמן התאוששות ויעד אובדן נתונים לפי צורכי העסק.

לפני עלייה לאוויר, שחזרו בפועל למסד ולתיקיית מסמכים מבודדים. בדקו ספירות ורשומות מדגמיות, התאמת קבצים לרשומות, כניסה וסיכומי חודשים. אין לכוון בדיקת שחזור למסד הפעיל. חזרה לגרסת קוד קודמת אינה מבטלת מיגרציות; בדקו תאימות לסכמה או השתמשו בתהליך שחזור מתורגל.

## המשך מתועד

אימות מקומי: 280 בדיקות Backend עברו, בדיקות הטיפוסים וה־lint ב־Backend עברו ובניית Frontend הצליחה. ה־lint ב־Frontend מסתיים עם אזהרות Fast Refresh קיימות. בדיקת Edge אוטומטית אימתה כניסה, HttpOnly, היעדר טוקן ב־localStorage, רענון ויציאה. תבנית NGINX עברה `nginx -t` ב־WSL עם תעודה זמנית ופורטים גבוהים; זו אינה בדיקת HTTPS מקצה לקצה של שרת הייצור.

נדרשים עדיין אימות בפריסה הציבורית, תרגול שחזור, ניטור תקלות וסינון לוגים פיננסיים קיימים לפני פתיחה לקהל. פיצול מסכים גדולים, בדיקות משתמשים וקורא מסך ובדיקות עומס הם שלבי המשך; בדיקות הבנייה והאינטגרציה אינן מחליפות אותם. עקרונות ומקורות: [סקירת הארכיטקטורה](production-architecture-review.md).
